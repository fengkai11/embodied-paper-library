# 具身研读 · 网站设计 V0.2

## 目标与定位

这个网站服务一个反复发生的动作：回到一篇读过的论文，迅速恢复对问题、机制、证据与局限的理解，然后决定下一步要比较什么、验证什么。

主仓库为 `fengkai11/embodied-paper-library`。内容通过 GitHub 管理，网站负责阅读和检索。当前原型遵循既定 Markdown + VitePress + GitHub Pages 方案。

V0.2 将**图像时间线**作为主要回看入口：先凭任务场景或论文图认出工作，再沿着问题理解方法，最后进入精读笔记。首批范围仍是现有 7 篇论文，覆盖 2023—2025 年的首次公开稿；这是个人阅读选集，不以覆盖全部具身智能研究为目标。

交互参考 [AIMAN.World 时间线](https://www.aiman.world/timeline) 的横向时间轴、全局浏览与节点详情。我们借鉴其阅读方式，内容继续聚焦论文问题、方法和研究比较。

## 三个主要场景

| 场景 | 页面任务 | 成功标准 |
| --- | --- | --- |
| 隔一段时间回看 | 首页返回最近浏览，以图片识别论文；论文页给出30秒回忆 | 能快速说清研究问题与关键机制 |
| 多篇之间建立判断 | 图像时间线按年份与问题串联，专题采用统一维度比较 | 不混淆算法目标、数据和实验条件 |
| 从阅读走向动手 | 每篇链接到最小实验，计划与结果独立记录 | 知道下一步验证的假设、基线与指标 |

## 信息架构

| 主入口 | 内容与交互 |
| --- | --- |
| 研究首页 | 带图阅读入口；访问后的最近浏览；图像时间线入口；论文列表；研究追问；专题入口 |
| 论文库 | 论文缩略图；按类别筛选；检索正文；按初稿年份或标题排序；收藏 |
| 图像时间线 | 通用策略、经验学习、世界模型、接触装配四个问题筛选；横向浏览、选中详情与精读入口 |
| 专题比较 | 从共同问题比较方法、数据、反馈、推理和工程成本 |
| 实验记录 | 假设、基线、指标、资源与验收标准；首版只展示明确标记的候选实验 |
| 复习中心 | 先看问题，展开参考要点；主动标记与撤销，保留真实日期 |

收藏、精读模板和使用指南放在辅助导航，避免主菜单膨胀。

## 首页布局

桌面采用固定深色侧栏和浅色主区。顶部保留面包屑与全站搜索。首屏的重点阅读卡使用作者图像，配当前研究问题和精读入口；图像时间线入口提示论文之间的时间与问题关联。论文列表使用真实缩略图帮助识别，专题继续把独立阅读连接为研究线索。

不使用掌握百分比、连续打卡或虚构任务进度。收录数量、类别数量和专题数量由真实内容生成。新访客显示推荐入口；有本机浏览记录时才显示最近访问论文。

## 图像时间线

### 一条轴，四个问题入口

横轴按首次公开稿年份分为 2023、2024、2025，图片节点在轴的上下交错排列。节点显示论文名、年份、研究类别和一句方法线索。时间线以节点可读性分配空间，**间距不表示真实时间跨度**；同年排序用于阅读导航，不推断方法的因果关系。

| 研究问题 | 首批论文 | 阅读焦点 |
| --- | --- | --- |
| 通用策略 | π₀、π₀.₅、π*₀.₆ | 从动作表示与数据走向泛化，再看经验如何改进策略 |
| 从经验中学习 | HIL-SERL、TD-MPC2、π*₀.₆ | 示范、干预、价值与任务反馈怎样进入学习闭环 |
| 世界模型 | TD-MPC2、DINO-WM | 控制潜表示与视觉特征表示分别保留什么信息 |
| 接触与装配 | IndustReal、HIL-SERL | 仿真迁移、真实交互与失败后的纠正 |

每篇论文只占一个时间节点，多条研究问题可以筛出同一篇论文。保留首批 7 篇，后续按实际精读工作逐篇补充。

### 从全览到详情

- **全览 / 详看**切换节点和画布尺寸，保证文字保持可读；左右按钮与原生横向滚动提供等效操作。
- 选择节点后，在画布下方显示完整图片、研究问题、一句机制、关联比较，以及原文和精读笔记入口。
- 选中论文通过 `paper=slug` 写入页面 URL，例如 `routes.html?paper=hil-serl`，可直接返回同一节点。
- 图片可放大，图注持续说明它是任务展示、仿真演示还是论文方法图。
- 关联比较写出共同问题和差异；同系列关系与跨方法比较分别表述。没有文献证据时，不使用“继承”“基于”等因果描述。

### 手机阅读

窄屏切换成按年份排列的纵向图像卡片，继续保留研究问题筛选。点选后在节点旁展开详情，避免在画布与页面底部之间来回寻找。图片、按钮、正文在屏幕宽度内排版，论文图保持完整比例。节点使用可聚焦的 DOM 按钮，选择状态同时通过文字、边框和 `aria-pressed` 表达。

## 图像与证据

图像按用途分工：缩略图帮助回忆是哪一篇，详情大图帮助观察任务或方法，正文图表承担机制与实验证据的解释。

| 图像类型 | 可以帮助回答 | 呈现要求 |
| --- | --- | --- |
| 作者任务图或视频静帧 | 机器人在什么环境中做什么 | 标注任务或演示来源；视频静帧记录时间位置 |
| 作者仿真图 | 任务、环境与控制目标是什么 | 明确写“仿真”，不当作实机实验结果 |
| 作者论文方法图 | 模块怎样连接，信息如何流动 | 保留模块、图例与完整比例，尽可能注明图号 |
| 本站整理的关系图 | 如何比较方法或提出研究追问 | 以文字说明是整理与推断，并链接相应论文 |

素材放在 `docs/public/papers/`；来源清单为 `design/image-sources.json`，按论文 `slug` 记录本地路径、原图或视频地址、来源页、中文 alt、图注、类型、作者 credit 和处理方式。使用 `object-fit: contain` 保留完整图像；压缩改变文件体积，不增删图中信息。

作者任务照片只用于说明场景，不能被标作算法机制、实验效果或本站复现证据。图注和来源链接随图片展示，不让读者只能从配色或图片外观猜测证据类型。

## 阅读页

正文宽度控制在约780px，16px正文、约1.9行高。桌面右侧保留目录，窄屏将目录折叠在正文前。每篇先展示来源、初稿年份、整理状态与可放大的作者图像，再进入：

1. 30秒回忆：问题、方法、最需要保留的限制。
2. 研究问题与方法机制。
3. 公式及变量说明；必要的关系图。
4. 实验证据、消融和结论范围。
5. 理解自测与后续追问。
6. 最小实验、基线和评价指标。
7. 原文来源和关联论文。

视觉上以段落层次和留白为主，不依赖大量彩色徽章。事实、主张、推断和待验证使用文字标识；颜色不承担唯一含义。

## 视觉系统

| 元素 | 设计 |
| --- | --- |
| 导航 | 深蓝灰 `#1a1c29`，固定位置，便于跨论文往返 |
| 背景 | 冷白灰 `#f6f7fa`，与白色内容区保持轻微层次 |
| 强调 | 紫色 `#6657ce`，用于选择、行动和研究提示 |
| 类别 | 紫、蓝、青、暖棕的低饱和点缀；始终配文字 |
| 排版 | 系统无衬线字体，中英混排；阅读内容优先 |
| 图像 | 真实作者任务图、仿真图和论文方法图；完整比例、清晰图注与来源 |
| 时间轴 | 轻量网格背景、上下交错的图片节点、明确的选中状态；优先服务7篇阅读选集 |
| 动效 | 轻微悬停与焦点反馈；尊重减少动态效果设置 |

## 功能与数据边界

Markdown 是唯一共享内容源。构建时生成论文清单和全文索引。公式本地构建，不依赖访问外部数学服务。Mermaid 按需加载。

收藏、复习和最近浏览存入当前浏览器。浏览器存储不可用时显示说明；不冒充账号同步。原文、站内搜索和阅读本身仍可使用。

初版不加入在线内容编辑、用户登录或复杂知识图谱编辑器。改笔记走 GitHub，网站优先保证阅读与回看体验。后续如果出现明确的多设备同步或全文标注需求，再引入相应存储。

## 发布路径

设计预览采用私有访问，便于先评审体验。V0.1 已通过仓库 PR #1 合并。V0.2 在 `design/visual-timeline` 分支单独评审，本轮改造不等同于已经合并或发布正式站点。GitHub Pages 的实际上线状态以仓库工作流结果为准。

## 核验要点

以下是验收要求，核验结果以对应 PR 和发布记录为准。

- 7篇图片、年份、图注、来源与原稿一致，任务图和方法图的性质准确。
- 全览、详看、左右滚动和四个问题筛选均可使用；选中节点、详情内容与URL一致。
- 直接访问或刷新带 `paper` 参数的时间线能恢复选择，无效参数能回到默认节点。
- 窄屏为纵向图卡，选中详情就近出现，页面没有整体横向溢出。
- 大图弹层可用键盘进入，Escape关闭，关闭后焦点返回触发按钮。
- 全文搜索能定位正文中的词语，支持键盘选择、Enter打开、Escape退出。
- 论文筛选、排序、空结果与收藏均能实际使用。
- 复习答案默认折叠，标记后刷新仍在，撤销后计数更新。
- 论文页目录、来源、关联论文、公式和关系图可访问。
- GitHub项目子路径构建可用，刷新深层论文页不会丢失资源路径。
- 窄屏导航折叠，宽公式和表格在自身容器滚动。
- 笔记来源、整理状态与实验状态诚实呈现。
